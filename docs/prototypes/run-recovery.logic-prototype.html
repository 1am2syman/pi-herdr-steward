C11
Fixed reconciliation precedence

Check report, working/blocked, settled/no-report, unclear, then missing—in that order.

C12
Valid report found

Accept only after validating spec hash, commits/Artifacts, referenced logs, and report fields.

C13
Agent working or blocked

Continue observing; answer a block only when the approved Task already determines the answer.

C14
Settled without report

Ask the same agent once for the report; if still absent, block rather than infer success.

C15
Malformed report

Return once to the same agent for correction; if still malformed, block.

C16
Missing agent

Inspect preserved work first; never blindly repeat, reset changes, or delete partial progress.

C17
Transient failures

Provider/network interruption, startup failure, Herdr command failure, and unexpected exit consume the two-retry budget.

C18
Correctness failures are rework

Tests, findings, incorrect work, scope violations, and missing Artifacts do not consume transient retries.

C19
Recovery budget exhausted

After at most two replacement Attempts, mark needs-user and retain all partial work.

C20
Model retry discipline

Retry same model first; replacements use only next approved fallback; never change model inside an Attempt.

C21
Silence recovery ladder

Inspect → nudge → soft-interrupt stuck generation → resume same agent → replacement.

C22
Known external process alive

Set waiting-external; warning threshold only notifies; do not nudge, interrupt, replace, or demand output.

C23
External liveness unclear

Perform passive inspection and avoid destructive recovery; after exit, allow grace before the silence ladder.

C24
Herdr temporarily unavailable

Monitoring degrades, Attempts do not fail, and reconciliation resumes when Herdr returns.

C25
Produced evidence

Code Builder supplies local commit SHA; non-Git Artifacts use path, size, and SHA-256.

C26
Out-of-scope changes

Preserve and show them; return to Builder for correction before Review.

C27
Artifact integrity

Verify base SHA, head SHA, exact commit range, clean Builder worktree, commands, exit results, and durable logs.

C28
Independent Reviewer model

Use a separate agent and first available approved different-family model; same-family needs explicit user authorization.

C29
Frozen Review target

Reviewer evaluates the recorded revision; capture HEAD and dirty fingerprint before and verify both after.

C30
Reviewer modified worktree

Preserve changes, invalidate Review, mark needs-user, and never reset unexplained work.

C31
Review requests rework

Findings, conflict, failed check: Builder produces a new SHA and fresh Review; initial cycle plus at most five repetitions.

C32
Assignment changed unexpectedly

Preserve the changed specification and require user confirmation; do not accept the report against a different contract.

C33
Referenced evidence invalid

Missing commit, log, Artifact, or invalid report gets one repair chance, then blocks.

C34
Plain Markdown reports

Small machine-readable frontmatter plus concise role-specific evidence; full logs stay in durable files.

06

Parallel work and sequential integration

Mapped from: Initial Operating Model · Execution Policy · Parallelism and Integration · Artifact Integrity and Interrupted Side Effects

Clearly disjoint allowed scopes

  • Builder/Reviewer pairs may run concurrently.
  • Each code Builder owns an isolated worktree.
  • No arbitrary dependency graph is introduced.

Overlapping allowed scopes

  • Serialize in user-approved order.
  • Integrate in that same order.
  • Never integrate in completion order.
C35
Parallel only when scopes are disjoint

Overlap means serialization, not a general task dependency engine.

C36
Approved-order integration

Completed Tasks wait when needed; integration order never follows finishing time.

C37
Persist integration intention

Record target branch, target SHA, approved base/head range, and intended action before Git mutation.

C38
Exact range already integrated

Record success and do not apply the range twice.

C39
Target unchanged, range absent

The exact recorded integration side effect can be retried.

C40
Partial or conflicted Git operation

Preserve and show it; never blindly repeat, abort, reset, or revert.

C41
Integration target advanced

Compare with Task base; if revision needs modification, return to Builder for new SHA and Review.

C42
Approved revision conflicts

Builder updates against target, fresh Review is mandatory, and one rework cycle is consumed.

C43
Managed worktree changed externally

Preserve difference, invalidate evidence, stop mutating the Task, and require user confirmation.

C44
Deterministic final verification

Steward runs approved commands and records logs/exit codes; no deterministic check requires durable user waiver.

C45
Controller interrupted during verification

Wait on identifiable live process, consume complete durable result, or rerun only when no conclusive result exists; record rerun.

C46
Failure owner is clear

Responsible Task returns to Builder for new SHA and fresh Review; consumes a rework cycle.

C47
Failure ownership unclear

Preserve integrated state and ask user; never automatically reset or revert several interacting Tasks.

C48
Verification dirties checkout

Preserve generated/unexplained changes, block completion, and show exact difference.

C49
Completion succeeds

Mark completed, archive Journal/reports, notify, and retain worktrees until confirmed cleanup.

09

Revision, cancellation, completion, and cleanup

Mapped from: User Surface · Execution Policy · Verification and Cleanup

/steward revise

  • Draft and confirm explicit delta.
  • Identify affected Tasks and evidence.
  • Version changed specifications.
  • Cancel obsolete Attempts and invalidate affected Reviews.
  • Retain unaffected completed work.

/steward cancel → /steward cleanup

  • Persist cancellation before interrupt.
  • Stop new dispatch and integration.
  • Preserve reports, sessions, panes, worktrees, logs.
  • Show exact owned cleanup set and ask confirmation.
C55
Explicit Run revision

Ordinary conversation never mutates scope; only confirmed delta changes specs and invalidates affected evidence.

C56
Cancellation is durable first

Mark Run cancelled before interrupting; prevent further dispatch/integration and preserve all evidence.

C57
Graceful terminal shutdown

After complete or cancel, stop Steward-created agents but retain Pi sessions, panes, worktrees, reports, and evidence.

C58
Confirmed owned-resource cleanup

Close retained Steward panes and remove managed worktrees only; retain archived Journal, Assignments, reports, and logs.

C59
Both Journal snapshots invalid

Enter read-only recovery and ask the user; never invent mutable state.

C60
Unsupported schemaVersion

Newer or unmigrated older Journal opens in read-only status mode; never guess a migration.

C61
Project-local sensitive data

.pi/steward is ignored, user-only where supported, least-data Assignments, and full logs require warning before display/export.

C62
Historical evidence retention

Archive final snapshots; ordinary cleanup keeps history until the user explicitly deletes an archive.

C63
Separate authorization boundary

Push, deploy, force reset, discard, delete unrecognized resources, and account/security changes always need explicit authorization.

C64
Interactive-mode boundary

Full behavior is Pi TUI only; plain status may work elsewhere, but approval/takeover/revision/cancel/config/cleanup require interaction.
